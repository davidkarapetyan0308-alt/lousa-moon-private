# LOUSA BOX: задание на следующую продуктовую итерацию

## Контекст

Текущий исходник уже содержит первую безопасную переработку заказа BOX:

- пользователь начинает с оценки потребности, а не с навязанного тарифа;
- количество средств является точным и редактируемым;
- после двух заполненных циклов используется фактический расход;
- тестовая оплата явно обозначена и не списывает деньги;
- frontend и backend используют одинаковые цены: Essential `8 900 AMD`, Comfort `14 900 AMD`, Moon Ritual `22 900 AMD`;
- обновлены изображения трёх коробок.

Не откатывайте эти изменения и не удаляйте существующие данные, сессии, заказы, подписки или серверные контракты.

## Цель

Доведите сценарий заказа LOUSA BOX до цельного, спокойного и профессионального checkout:

1. Потребность.
2. Состав.
3. Уровень BOX.
4. Доставка.
5. Проверка и оплата.

Никаких лишних менструальных средств нельзя добавлять автоматически только ради заполнения тарифа. Тариф - это уровень сервиса, вместимость и включённые дополнения; состав определяется пользователем.

## Обязательные правила

- Рекомендация не является медицинским советом и всегда редактируется.
- Используйте исторический расход только при двух и более валидных циклах.
- Стартовые ориентиры: лёгкая интенсивность - около 3 средств/день, обычная - около 4, обильная - около 6.
- Диапазон выбора: 8-48 средств.
- Сервер - источник истины для финальной цены.
- Любое изменение состава сбрасывает устаревший server quote.
- Тестовая оплата должна быть названа тестовой. Реальное списание не имитировать.
- Ошибки аллергенов должны быть понятны пользователю; не показывать raw error codes.
- Поддерживать `ru`, `en`, `hy`, guest mode, offline/local режим, Firebase и API-режим.

## Дизайн

- Использовать существующую палитру LOUSA Moon.
- Не делать карточки внутри карточек без реальной необходимости.
- Важны белое пространство, крупное количество средств и прозрачная цена.
- Включённые заботливые дополнения показывать отдельно от менструальных средств.
- У дополнений должна быть видна цена до выбора.
- Финальный экран обязан показывать: уровень, точное количество, дополнения, адрес, окно, доставка, итог и тип оплаты.

## Проверка перед передачей

Выполнить:

```bash
npm run typecheck
npm run lint -- --quiet
npm test -- --runInBand tests/boxNeedEstimator.test.ts tests/boxQuote.test.ts tests/allergenSafety.test.ts
```

Не собирать APK до зелёных проверок. После изменения backend обязательно проверить `/ready` на HTTP 200.
