# LOUSA MOON — отчёт по UX/UI и продуктовой переработке

Дата фиксации: 28 июля 2026  
Исходная версия: 1.18.22, Android build 133  
Статус: **готово к продолжению внутреннего QA после восстановления зависимостей и Android-среды; не готово к публичному релизу**.

## 1. Что было найдено

- Нижняя навигация не соответствовала целевой информационной архитектуре: профиль не был самостоятельной основной вкладкой.
- Первый запуск не давал короткого последовательного сценария с одним вопросом на экран и сохранением незавершённого прогресса.
- Главный экран и LOUSA BOX местами показывали много равнозначных карточек вместо одного очевидного следующего действия.
- Состояния уведомлений могли расходиться с системным разрешением Android.
- Пользовательские ошибки местами содержали технические формулировки и не всегда давали понятное восстановительное действие.
- Адрес доставки мог отображаться слишком общо и не всегда называл конкретно отсутствующее поле.
- Гостевой и зарегистрированный профили требовали более чёткого разделения.
- Стартовая сцена и PNG-ресурсы имели риск тяжёлой композиции и лишнего веса.
- Не было отдельного скрытого developer-only экрана для технической диагностики.
- В handoff отсутствуют полноценные `node_modules`, production-переменные и локально доступный Gradle-дистрибутив; в среде отсутствует `adb`.

## 2. Что было исправлено

### Информационная архитектура

- Нижняя навигация приведена к четырём разделам: **Сегодня, Календарь, LOUSA BOX, Профиль**.
- Профиль подключён как основная вкладка; поддержка, уведомления и настройки остаются внутри профиля/вторичных маршрутов.

### Первый запуск

- Реализован пятишаговый onboarding:
  1. дата начала последнего цикла;
  2. обычная длительность цикла;
  3. длительность менструации;
  4. напоминания;
  5. адрес LOUSA BOX.
- Один вопрос на экран, прогресс, назад, пропуск необязательных шагов, финальная проверка.
- Черновик хранится в защищённом локальном хранилище и восстанавливается после перезапуска.
- Дата цикла начинается пустой и требует явного выбора.
- Гостевой onboarding не запускает серверную синхронизацию; зарегистрированный пользователь синхронизируется только в API-режиме.

### Сегодня и Календарь

- Главный экран ориентирован на состояние цикла и одно следующее действие.
- Пустое состояние цикла содержит причину и кнопку добавления даты.
- Формулировки изменения/удаления даты упрощены; добавлены предупреждения о влиянии изменения на прогноз и напоминания.

### LOUSA BOX и адрес

- Первый экран BOX показывает продуктовый статус, доставку, адрес и следующее действие.
- Частичный адрес не выдаётся за завершённый.
- Ошибка адреса сообщает конкретное отсутствующее поле.
- Поля адреса отображаются структурированно; `region` больше не подменяет `корпус`.
- API-контракты и сервер расширены для дополнительных структурированных полей адреса.

### Профиль и гостевой режим

- Отдельные состояния гостевого и зарегистрированного профиля.
- Для гостя показано, что данные хранятся на устройстве, и доступен переход к созданию/входу в аккаунт без удаления локальных данных.
- Для зарегистрированного пользователя отображаются сохранённые email, телефон, язык и состояние уведомлений.
- Подтверждения выхода и удаления сохранены.

### Уведомления

- При системном запрете категории визуально отключены и недоступны.
- После возврата из настроек разрешение перечитывается без перезапуска.
- Ручное обновление показывает результат и время последней синхронизации.

### Поддержка и ошибки

- Темы поддержки приведены к понятным пользовательским категориям.
- Технические ошибки заменены на короткие пользовательские сообщения с действием восстановления.
- Технические детали доступны только на скрытом debug-экране в development-сборке.

### Стартовая сцена

- Таймлайн запуска сокращён примерно до 2,9 секунды в обычном сценарии.
- Упрощено центральное облако, сохранено центральное положение логотипа.
- Оптимизированы 6 PNG стартовой сцены: суммарно с 1 837 020 до 1 697 077 байт, уменьшение на 139 943 байта (около 7,6%).
- Сохранены fallback и тайм-ауты, препятствующие бесконечной блокировке запуска.

## 4. Проверенные сценарии

### Проверено статически

- целостность маршрутов;
- нижняя навигация и safe area;
- минимальные touch targets;
- геометрия и scrollability onboarding;
- UX-копирайтинг;
- отсутствие выдуманного прогноза цикла;
- гостевой режим и переход к аккаунту;
- сохранение локальных данных;
- OpenAPI/route parity;
- product recovery guards;
- стартовый Paper Moon entry и навигационный handoff;
- согласованность версии/build number.

### Не проверено на физическом Android

Все 28 обязательных device-сценариев из задания, включая холодный запуск 5 раз, offline/slow network, системные уведомления, Google/email/phone auth, доставку, возврат из фона, разные размеры экрана и увеличенный шрифт. Причина: в среде отсутствует `adb` и подключённое устройство.

- no legacy BOX actions;
- BOX quality policy;
- route integrity;

- bottom safe area;

- complete product recovery;
- Paper Moon entry;

- build 130 root navigation;
- Google auth build 128 contract;
- UX system rebuild;
- guest mode.

Подробности: `qa-artifacts/logs/static-verification-final.log`.

### Не удалось запустить полноценно

- `npm run typecheck`: отсутствуют реальные Expo/React/React Native typings и базовый Expo tsconfig из зависимостей.
- `npm run lint`: `eslint` отсутствует.
- `npm test`: `jest` отсутствует.
- `npm run test:integration`: `jest` отсутствует.
- `npm ci --offline`: офлайн npm-кэш не содержит необходимые пакеты.

Это означает, что **typecheck, lint и Jest нельзя считать пройденными**.

## 6. Оставшиеся проблемы

Приоритет P0 / блокеры:

- Нет сборки APK после изменений.
- Нет установки APK и проверки на физическом Android.
- Нет полного typecheck/lint/Jest/integration run.
- Нет production environment values и ключей.
- Gradle wrapper не может скачать `gradle-8.10.2-all.zip` без сети/локального кэша.

Приоритет P1:

- Нужен runtime-review всех локализаций и адаптивности на 320 dp и при увеличенном системном шрифте.
- Нужен TalkBack-проход и проверка порядка фокуса.
- Нужны реальные backend/auth/delivery/notification сценарии.

## 7. APK и SHA-256

- APK после изменений: **не создан**.
- SHA-256 APK: **не существует**.

Причины:

1. обязательные production-переменные не предоставлены;
2. Gradle-дистрибутив отсутствует в локальном кэше и недоступен без сети;
3. отсутствует Android-устройство/`adb` для установки и проверки.

## 8. Ограничения и риски

- Статические проверки подтверждают архитектурные контракты, но не заменяют runtime QA.
- Без typecheck и Jest остаётся риск типовых и интеграционных регрессий.
- Без физического Android нельзя подтвердить отсутствие белого экрана, реальные тайминги холодного старта, поведение разрешений, клавиатуры, TalkBack и фонового восстановления.
- Без production-конфигурации нельзя подтвердить реальные авторизацию, API, доставку, карты и уведомления.

## 9. Скриншоты до и после

Скриншоты приложения не созданы: проект нельзя было запустить в Android runtime в текущей среде. Подменять их статическими макетами или заявлять визуальную проверку без запуска было бы недостоверно.
